# Автофакт — каталог СТО Минска

Nuxt 3 + TypeScript + Tailwind starter. Моковые карточки предназначены для демонстрации интерфейса: адреса, телефоны, рейтинги и график нужно заменить на подтверждённые данные до публикации.

## Запуск

```bash
npm install
npm run dev
```

## Структура

```text
assets/css/       дизайн-токены и базовые стили
components/       StationCard, StationFilters, skeleton
composables/      URL-фильтры, SSR-загрузка, график работы
pages/            каталог и динамические SEO-страницы
server/api/       валидируемый каталог СТО
server/utils/     демо-данные
types/            доменные типы
utils/            георасстояние и ссылки на карту
```

Сервис использует обычную пагинацию из-за предсказуемых deep-link URL, индексации и доступности с клавиатуры. Для мобильной выдачи можно заменить переходы по страницам на «Показать ещё», сохранив номер страницы в URL.

### Состояния и поведение

- **Default:** контрастная иерархия, цена и рейтинг на одной строке, один доминирующий CTA.
- **Hover/focus:** карточка слегка приподнимается; граница светлеет. Фокус-кольцо лайм с зазором 3 px.
- **Active:** выбранный фильтр получает лаймовую заливку и `aria-pressed=true`; кнопка имеет видимое нажатие.
- **Loading:** карточки-скелетоны повторяют реальную геометрию; shimmer отключается при `prefers-reduced-motion`.
- **Empty/error:** объяснение, простое действие «Сбросить фильтры»/«Повторить», без декоративной картинки ради картинки.

На мобильном поисковая строка и кнопка фильтров остаются в sticky-панели. Полный набор фильтров открывается в bottom-sheet; сортировка остаётся компактным select над выдачей. Так выдача не теряет полезную высоту экрана и выбранные фильтры видны в счётчике.

Микроанимации дают обратную связь: debounce-поиск не дёргает выдачу на каждую букву, карточки мягко перестраиваются после фильтра, CTA меняет яркость при hover/press, skeleton показывает форму ответа. Избыточные параллаксы и анимированные фоновые детали исключены.

Иконки — Lucide: `Wrench` ремонт, `ScanLine`/`Activity` диагностика, `CircleGauge` шиномонтаж, `Zap` автоэлектрика, `Phone` звонок, `Navigation` маршрут, `Clock3` режим работы, `MapPin` адрес.

Статус «Открыто» использует зелёный текст, круглую/clock-иконку и короткую подпись; статус не полагается только на цвет. Район и услуги разделены: район — текстовая географическая метка рядом с названием, услуги — чипсы ниже рейтинга. Район как чип отвлекал бы от услуг, которые помогают отфильтровать карточку.

## Типы и API

`types/station.ts` содержит `Service`, `Station`, `District`, `Filters`, включая координаты для сортировки по расстоянию. API `/api/stations` проверяет query через Zod, фильтрует, сортирует и возвращает страницу из 9 элементов. Сейчас данные демонстрационные.

## Архитектурные оговорки

- **Нужна множественная фильтрация:** URL хранит `service=remont,diagnostika&district=center`; это сохраняет совместимость с несколькими выбранными значениями. Для простого одиночного примера URL будет ровно `?service=remont&district=center`.
- Расчёт «открыто сейчас» следует запускать на клиенте и зафиксировать часовой пояс расписания как `Europe/Minsk` через `Intl.DateTimeFormat`. Текущий компактный composable использует локальный часовой пояс среды и может расходиться с Минском при другом timezone сервера.
- У мок-СТО недопустимо публиковать выдуманные контакты как реальные. Перед запуском проверить адреса, телефоны, режим работы, рейтинги, права на отзывы и получение согласия на карточки.
- CSS media query 1280/1440 расширяет контейнер; 3 колонки сохраняются, чтобы карточка оставалась читаемой. Четвёртая колонка на 1440 возможна после проверки длин адресов и CTA.
- Переключатель темы включён, но светлая палитра — стартовая адаптация. Перед продом нужно проверить каждый компонент на контраст WCAG AA и добавить раннюю установку темы до hydration, чтобы убрать возможную вспышку тёмной темы.

## SEO

`useSeoMeta` формирует title/description/OG из активных фильтров. JSON-LD строит `ItemList` с `AutomotiveBusiness` для элементов выдачи. Sitemap/robots подключены через `@nuxtjs/seo`, а route rules задают короткое SWR-кэширование API и prerender SEO-страниц. Для продакшена нужны реальные страницы услуг/районов с уникальным полезным текстом и canonical/noindex политика для произвольных комбинаций фильтров.

## A/B-гипотезы по звонку

1. Текст CTA «Позвонить» vs «Записаться по телефону» — измерять клики на карточку и подтверждённые обращения.
2. Телефон только за кнопкой vs видимый номер — проверить звонки и случайные нажатия отдельно.
3. Сортировка по рейтингу vs «открыто сейчас рядом» — сравнить звонки на 100 сессий, контролируя сезонность.
4. Карточка с ценовым диапазоном vs без цены — оценивать звонки и отказы после контакта.
5. Показывать «Проверенный сервис» рядом с названием vs бейдж в профиле — мерить CTR звонка без ухудшения доверия.
